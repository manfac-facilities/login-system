Ficha da obra — os três ajustes do feedback de 22/09

Rascunho de tela para você aprovar antes do código — quem vê direto no ar é o cliente (decisão de 22/09). Cor, tipografia e espaçamento são os mesmos do mockup J4 v03 aprovado; não estão em julgamento. Hoje, nos exemplos, é 22/09/2026. Dados de obras DPSP inventados, mas plausíveis.

  • Seção 1 — nome novo da etapa de desvio, nos dois caminhos da esteira.
  • Seção 2 — data de fechamento da OS: editável ao concluir, corrigível depois, com os dois erros pedidos.
  • Seção 3 — equipe/prestador em texto livre com sugestão, nos dois lugares em que aparece.
1

Nome da etapa de desvio

A etapa some do texto "Pendente fechamento" e passa a se chamar "Executado - pendente aprovação OS", do jeito que a v2 do mockup J4 já tinha aprovado. "Fechar OS" continua existindo nos dois caminhos — é o passo que nunca é pulado.

Reconciliado com o código real
  • Hoje o nome gravado é "Pendente fechamento" (app/obras/_lib/tipos.ts:165). É provável que esse nome antigo tenha causado o susto do cliente.
  • A esteira nunca pula "Fechar OS". O único desvio é a etapa aprovarOS, apagada apenas quando a OS já estava aprovada antes de a obra chegar nela (_ficha.tsx:238). Este mockup só troca o nome — a lógica do desvio não muda.

    Data de fechamento da OS

    Mesmo controle que já existe hoje — o select "Mudar a etapa desta obra". Quando o destino escolhido é "Pendente faturamento" saindo de "Fechar OS", aparece abaixo do select o campo "Data de fechamento da OS", pré-preenchido com hoje e editável, e só então a mudança é confirmada. Depois de concluído, o passo "Fechar OS" na esteira mostra a data com a ação "corrigir data".

    Reconciliado com o código real
    • Hoje marco_fechou_os é gravado automaticamente com a data de hoje ao trocar a etapa para fecharOS (_actions.ts, calcularMarcosDaEsteira) — sem campo de data, sem edição depois.
    • Não existe botão "Concluir" por passo em produção: a troca de etapa é sempre este mesmo <select> genérico ("Mudar a etapa desta obra", _etapa.tsx) com o botão "Confirmar mudança". Este mockup não inventa um controle novo — a única peça nova é o campo de data condicional, que aparece só nesta transição específica (Fechar OS → Pendente faturamento).
    • obras_historico já existe e já é usado para outros campos da ficha; usar o mesmo mecanismo para registrar a correção (quem, quando, de → para) não exige tabela nova.
