Frentes do Controle de Obras

Quem faz o quê, por quê, e em que ordem. O sistema controla obras de manutenção em lojas de uma rede de farmácias: a obra nasce como uma OS no Field Control, a equipe da Manfac responde um diário todo dia, e o sistema acusa quando uma obra para de andar. Esse último ponto é a razão do projeto existir — a obra que ficou 123 dias parada sem ninguém notar.

01

Como o trabalho foi dividido

O critério não é tamanho de tarefa. São três coisas, nesta ordem de peso.

1 · Credencial

O que só uma pessoa consegue executar não é divisível. Supabase, push, deploy e a planilha do cliente estão atrás de credencial do João.

2 · Canal com o cliente

Frente que depende de decisão do cliente fica com quem fala com ele. Há duas perguntas em aberto agora, e as duas mudam código.

3 · Sobreposição de arquivo

Duas frentes que editam o mesmo arquivo não rodam em paralelo sem merge doloroso. Este critério gerou a única restrição de ordem deste documento.

03

A única restrição de ordem

Se só uma coisa deste documento for lembrada, que seja esta.

1a e F3 editam o mesmo arquivo

app/obras/obra/[id]/_actions.ts — a Triagem grava lá, e os marcos precisam ser gravados na troca de etapa, que também mora lá. Tocar as duas ao mesmo tempo garante conflito de merge no arquivo mais delicado do módulo.

Por isso o Duda começa pela F1, não pela F3. A F3 entra depois que a 1a estiver mergeada. A F1 é pasta própria e não colide com nada.

João
0 · no ar→ 1a · campos editáveis→ 1c · sync do Field
Duda
F1 · cliente da API→ F2 · smoke test→ espera merge da 1a→ F3 · colunas mortas

A F1 não bloqueia nada e nada bloqueia ela. Ela também alimenta a 1c do João: quanto antes a camada de cliente existir, mais cedo a sincronização pode ser desenhada em cima dela. A F2 só depende de a migration ter rodado.

04

Os arquivos do projeto

Os três documentos que o Duda carrega na inteligência dele antes de começar. Cada um tem um botão para copiar o conteúdo inteiro.

Como usar

Copie os três e salve como arquivos .md na raiz do projeto do Duda — ou cole o conteúdo no arquivo de instruções que a ferramenta dele usa (CLAUDE.md, AGENTS.md ou equivalente).

A ordem de leitura importa: contexto primeiro, regras depois, frentes por último. O arquivo de frentes assume que os outros dois já foram lidos.

05

Para começar

Na ordem. O passo 1 é do João; os outros são do Duda.

1

Acessos. Supabase da Manfac como Developer — roda SQL, escreve no banco, cria bucket, e não apaga projeto, não mexe em cobrança, não convida ninguém. No GitHub, Write no repositório. Convite por e-mail, conta própria — login não se compartilha.

2

Ler antes de escrever qualquer linha. Os três arquivos acima, e o AGENTS.md da raiz do repositório — a fonte de verdade operacional sobre infra, banco e as armadilhas que já custaram dias.

3

Subir o ambiente e confirmar que o verde bate antes de mudar nada.

# Node 20 (.nvmrc)
npm install
npm run dev
npx jest app/obras   # espere 204 / 204
npm run lint
npm run build

Atenção: npx jest sem filtro deixa sete suites vermelhas, de manfac-site/ — o site institucional, que é outro app no mesmo repositório. Isso é conhecido, esperado, e está fora do escopo.
